# 自动换挡执行控制 v3 · 独立方向确认

## 目标与默认状态

- 本版在已实测的候选判断上增加可选执行路径，仍保留原有 P4-CAN 功能。
- 执行开关保存到设备 NVS 命名空间 `gearshift`，默认关闭；固件刷新或重启后仍保持用户选择。关闭再打开执行开关不会绕过单次刹车限制。
- 首页“实际换挡执行”开关和执行参数不再只是浏览器 localStorage；开启时会 POST 到设备并持久保存。

## 两阶段预判断

- 未踩刹车时持续计算候选，页面显示 `已预备 D/R · 踩刹车执行`。
- 踩刹车只做最后授权；执行服务周期 10ms。候选在松刹时稳定 100ms 后预备，踩下时不再重复等待稳定窗口。最终门禁或模板在踩下瞬间不满足时，本次不执行；保持刹车后恢复也不会补发，必须松刹重踩。
- 刹车已踩住时才出现的新候选不会执行，必须松刹后重新踩下。
- 雷达/原车配对仍按两阶段预备；踩刹车边沿时若候选已有效，立即执行，不再经过方向盘角度。
- 雷达/原车无可执行候选时，P 与 D/R 手动方向盘改为刹车优先：踩下边沿记录方向盘基准角，刹车保持期间相对角度达到阈值立即执行。D/R 使用变化量绝对值，`-120° → -60°` 即达到 60°，不需要回到或越过 `+60°`。
- 手动方向盘路径同样先检查“允许自动换挡速度”。超过该速度时撤销基准角并显示 `VEHICLE_MOVING`，降回限速内必须重新取基准角；不会先显示角度确认再留给最终门禁拦截。彻底切断速度仍用于停止整套候选计算。
- `刹车＋方向盘确认`：D/R 挡在刹车基准角后任一方向变化达到 D/R 角度，立即切相反挡。
- `P挡方向盘确认`：2021 款 Model Y 标定为负相对角=左打；左打达到 P 角度请求 D，右打达到 P 角度请求 R。未标定车型拒绝 P 手动换挡。
- V12 距离候选与 V13/V14 配对候选共用预备授权器；V13/V14 使用独立的预判断接收缓存，旧只读诊断接口保留。
- Model Y Juniper 的 `0x255 + 0x12B` 配对字段实测约 1Hz：普通诊断仍按 300ms 撤销，执行预备单独保留 1500ms，避免页面在报文间隔中闪烁。挡位、刹车、车速、车门等最终安全输入仍要求 300ms 新鲜。
- Model Y Juniper 实测踩刹车为驾驶员状态 2 且 apply 位 0。仅该车型档案的最终授权使用 `MODEL_Y_JUNIPER_DRIVER_STATE_2`，apply 位仅诊断；其他档案仍强制驾驶员状态 2 加 apply 1。Juniper 的车速总线应选择 BODY。
- 输入仍要求 300ms 新鲜；HTTP 显示按最短剩余有效期撤销，不因轮询续期。
- 页面加载设备参数，修改参数后即使实际执行关闭也保存到设备；参数变化撤销旧预备，开关变化不会重置已消耗的刹车次数。

## 彻底切断时速

默认参数为冷却 200ms、P 方向 15°、D/R 方向 30°、障碍距离 60cm。`hardCutKph` 默认 10，范围 1–30，且必须大于等于允许自动换挡速度。超过该速度后预判断和执行候选全部清空，跳过雷达扫描解码、候选与方向盘规则计算，接收侧旧候选窗口也暂停；执行服务降频到 100ms，仅保留 CAN 接收缓存和恢复所需的车速检查。降回阈值以内后重新建立预备，踩住刹车不会自行恢复授权，状态显示 `HARD_SPEED_CUT`。

## 三个独立确认开关

- D/R 方向确认（兼容参数 `steeringFallback`）：仅在雷达/原车无可执行候选时启用；踩刹车记录基准角，任一方向相对变化达到 `drDeg` 后立即切相反挡。
- P 方向确认（`parkSteeringFallback`）：P 的方向盘选择独立；踩刹车记录基准角，左打相对变化达到 `pDeg` 请求 D，右打请求 R，不读取 D/R 开关或雷达确认角。
- D/R 雷达方向确认（兼容参数 `requireSteering`）：只在 D/R 档 RADAR 来源候选上生效。关闭时雷达候选踩刹车立即执行；开启时踩刹车边沿记录方向盘基准角，相对变化达到 `obstacleDeg` 后立即执行。P 档完全忽略该开关；原车配对、P 方向确认和 D/R 手动方向确认不受它限制。刹车期间雷达候选丢失时不降级到 D/R 手动方向。
- 开关与角度输入框按三组显示；关闭仅禁用对应输入并置灰，保留原值。冷却、距离和速度属于共享条件，不随三个角度开关禁用。
- `prearm.source` 明确区分 `RADAR` / `VEHICLE_PAIR` / `P_STEERING` / `DR_STEERING`；另有 `sameGearIgnored` 和 `radarAvailable`，方向盘来源缺少雷达时显示“雷达未参与”。
- 配置记录版本更新为 2；v1 参数和角度保留，旧实际执行开关在迁移时关闭，需在新界面明确重新开启。v2 记录保存后继续持久恢复用户选择。

## 距离阈值

`obstacleCm` 默认 60 cm，范围 1–499 cm。D 档前方最近回波超过阈值时不给 R，保持 D；R 档后方最近回波超过阈值时不给 D，保持 R；P 档仅阈值内回波参与前后比较；两侧均无阈值内回波（包括 NO_OBJECT 或远于阈值）时默认给 D。`1` 表示 NEAR_DETECTION，没有可用距离，始终按阈值内处理；`500` 是 NO_OBJECT，不是 500 cm。

## 执行条件

实际发送前必须同时满足：

1. 当前车型拓扑为 BODY/CHASSIS/PARTY 三路 CAN，三路均为 RUNNING，且 CAN 发送未被维护/USB 抓包/管理状态阻塞。
2. 候选来自已选来源，且在踩刹车之前已经预备：V12 简化距离规则、V13/V14 `0x255 + 0x12B` 配对字段或已开启的方向盘选择。
3. CHASSIS `0x145` 刹车解释为驾驶员状态 2，且 apply 位为 1，并仅在驾驶员状态由松开到踩下的有效边沿执行；apply 位跳变不是新的踩刹车。输入失效/过期不视为松刹。
4. `0x118` 实际挡位为 P/D/R，目标挡位不同于当前挡位。
5. 加速踏板为 0，车速不超过配置值（0–8 km/h），四车门和后备厢均为关闭。
6. 安全带开关开启时要求 MUX0 安全带原始值为扣合。
7. 使用方向盘来源、或雷达候选开启雷达确认时，要求转角报文有效且达到该来源自己的角度。
8. BODY 线上真实请求模板新鲜且累计至少 5 帧：V12 使用 `0x229`，V13/V14 使用 `0x678`。模板校验失败、过期或样本不足则不发送。

## 请求构造

不使用固定载荷。发送时复制最新原车模板，仅修改请求/计数/校验字段：

- V12 `0x229`：请求码 P=0、R=2、D=4，计数 +1，`d0` 按两张参考表 XOR 重算，P 请求设置 `d2[1:0]=1`。
- V13/V14 `0x678`：`d1` 高 4 位 P=1、R=2、D=4，低 4 位计数 +1，`d0 = (0x7E + sum(d1..d6)) & 0xFF`。

## 一次动作和确认

- **每一次刹车踩下只允许提交一次 CAN 请求**。确认后即使候选立即反向，也必须先松开刹车、再重新踩下，并经过配置冷却后才可重新布防；成功动作默认冷却 200ms，失败恢复至少等待 1500ms。
- 后续 `0x118` 实际挡位达到目标则记录 `CONFIRMED`。
- 1500 ms 未确认记录 `FAILED`，同一次踩刹期内绝不重试；必须松开刹车后重新踩下，才允许新的安全候选重新布防。
- TWAI 提交失败也记录 `FAILED`，同一次踩刹期内不会重试。
- TX accepted 只代表请求进入 CAN 控制器，不代表车辆完成换挡；状态页单独显示确认计数。状态 `BRAKE_ACTION_USED` 表示本次刹车动作已消耗，继续踩着刹车、回 P 或关闭再打开执行开关都不会再发第二帧。

## 接口

- `GET /api/gear-hint/shift/status`：读取执行开关、参数、模板计数、安全输入、状态机、发送结果和原始最后请求。
- `POST /api/gear-hint/shift/config`：保存执行开关和参数。参数包括 `protocol`、`speedBus`、`requireSeatbelt`、`requireSteering`、`maxKph`、`cooldownMs`、`pDeg`、`drDeg`、`obstacleDeg`、`obstacleCm`、`steeringFallback`、`parkSteeringFallback`、`hardCutKph`。
- 恢复出厂设置会清除 `gearshift` 配置，执行开关回到默认关闭。

## 验证边界

编码器和门禁有主机测试；本版未声明车辆级安全认证。目标方向是否可通行、雷达健康、完整扫掠路径、驾驶员意图和所有车型差异仍由现场人员判断。执行开关开启前，应先在空旷场地按只读模式确认候选、刹车、车速、车门、安全带和模板计数。
